Я хочу изменить способ хранения конфигурации в проекте. Сейчас она находится в файле /config/config.toml. Мне нужно, чтобы она хранилась в базе данных SQLite. Вот список требований:

1.  **Множественные конфигурации:** Должна быть возможность иметь несколько различных конфигураций разных параметров сжатия. Каждая конфигурация должна иметь уникальный идентификатор. Предусмотреть поле "active" для активной конфигурации.
2.  **Хранение в SQLite:** Конфигурация должна сохраняться в файле базы данных SQLite по пути `/db/config.db`. Если директория `db` или файл не существуют, их нужно создать.
3.  **Pydantic Модель:** В каталоге `/models` необходимо создать Pydantic модель, которая будет описывать структуру конфигурации. Это обеспечит валидацию данных и удобство работы.
4.  **ORM:** Для взаимодействия с базой данных используй ORM. Я предпочитаю **Tortoise ORM**, но если это будет слишком сложно, то можно использовать нативную библиотеку `sqlite3`. Помоги мне решить, что лучше в данном случае.
5.  **Первоначальная Загрузка:** При инициализации проекта конфигурация должна автоматически загружаться из файла /config/config.toml. Конфигурация выбирается по параметру "active".
6. ** Бэкап конфигурации** Предусмотреть выгрузку конфигурации в файл /config/config_backup.toml
7.  **Загрузка при старте:** При запуске программы (или инициализации CLI) конфигурация должна автоматически загружаться из базы данных.
8.  **Изменение конфигурации:** Должна быть возможность изменять существующие конфигурации (например, через команды CLI или интерактивное меню).
9.  **Сохранение изменений:** Любые изменения конфигурации должны автоматически сохраняться обратно в базу данных.
